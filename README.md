# TX32F01 — Bootloader, FreeRTOS port, and a tiny cooperative scheduler

End-to-end bring-up of a **Cortex-M0 / 32 KB Flash / 4 KB SRAM** MCU
(TX32F01), validated on hardware. Three deliverables:

| Component | What it is | Resource cost |
|---|---|---|
| **`BOOTLOADER/`** | 8 KB bootloader with **YMODEM-1K** UART upgrade and CRC-protected image meta | 4 KB Flash, 1.6 KB SRAM |
| **`APP_RTOS/`** | Bare-metal **FreeRTOS V10.6.2** port (training / research path) | 3.5 KB Flash, 1.6 KB SRAM |
| **`APP_COOP/`** | Production-grade **cooperative scheduler** (80 LoC), runs behind the bootloader and is OTA-able | 2 KB Flash, **0.6 KB SRAM** |

All three are built with **Keil MDK-ARM V5 (ARMCC 5.06)** and have been
flashed/run on real silicon via SWD (J-Link OB).
The cooperative scheduler image was also delivered over UART YMODEM via
the bootloader — full end-to-end OTA path verified.

## Flash partition

```
0x01000000 ┌─────────────────────┐
           │  Bootloader   8 KB  │
0x01002000 ├─────────────────────┤
           │  Application 22 KB  │  ← APP / APP_COOP link here
           │                     │
0x01007800 ├─────────────────────┤
           │  App meta     1 KB  │  ← {magic, app_size, crc16}
0x01007C00 ├─────────────────────┤
           │  Boot flag    1 KB  │  ← APP writes 0xA55AF00D + reset → BL waits
0x01007FFF └─────────────────────┘
```

The Cortex-M0 has **no VTOR**, so APP interrupts physically dispatch
through the bootloader's vector table. We solve that with a 96-byte
**soft-vector table at `0x20000000`**: the bootloader's `*_Handler`
trampolines look up an APP-registered function pointer there and forward
the call. APPs register handlers via `app_softvec_register_irq()` in
[APP_PATCH/app_softvec.h](APP_PATCH/app_softvec.h).

## Quick start

### Build the bootloader (one-time per board)
```text
1. Open BOOTLOADER/TX32F01_BL.uvprojx in Keil μVision V5
2. F7 (Build) — expect "0 Error(s), 0 Warning(s)", ~5 KB code
3. F8 (Download) via J-Link / DAPLink, SWD
```

### Build & OTA-flash a new APP
```text
1. Build APP_COOP (or your own APP_PATCH-compliant project)
2. Locate Objects/firmware.bin (auto-generated by fromelf post-build)
3. From PowerShell:
   .\ymodem_send.ps1 -ComPort COM4 -BinPath .\APP_COOP\Objects\firmware.bin
4. ~3 seconds later: APP runs.
```

### Verify with any terminal
115200 8N1 on the same UART (GPIO3 P07=TX / P06=RX):
- Bootloader prints `[BL] alive` heartbeats while waiting
- COOP demo prints `[COOP] status tick=N heartbeat=... flash_seq_runs=...` every second
- RTOS demo prints `[RTOS] uart_task tick=N` every second

## FreeRTOS vs Cooperative — concrete numbers on this MCU

| | FreeRTOS (APP_RTOS) | Cooperative (APP_COOP) |
|---|---|---|
| Scheduler LoC | ~12000 | **80** |
| Flash | 3592 B | **2040 B** (-44%) |
| SRAM | 1688 B | **592 B** (-65%) |
| Min stack per task | 256 B | **0** (shared main stack) |
| Preemption | yes (via PendSV) | no (run-to-completion) |
| Sync primitives | mutex, queue, semaphore, notify | volatile + state machines |
| OTA-able via this BL | yes | yes |
| Bootloader integration | trivial (kernel uses SVC/PendSV/SysTick; trio renamed via 3 #defines so they override the WEAK startup symbols) | needs `app_softvec_register_systick()` (1 line) |
| Recommended for | learning, complex synchronization, ≥8 KB SRAM parts | production on small CM0/CM0+ |

The FreeRTOS port is *bare-metal* (no bootloader) so it directly owns
the full 32 KB Flash. To run FreeRTOS behind the bootloader you need to
register `vPortPendSVHandler` / `vPortSVCHandler` /
`xPortSysTickHandler` via the soft-vector table (see APP_PATCH).

## Hardware

- Target: TX32F01 (Cortex-M0, 24 MHz, 32 KB Flash, 4 KB SRAM)
- Debugger: J-Link OB (STM32F072), SWD
- UART: GPIO3 PIN07 = TX, PIN06 = RX, 115200 8N1
- LED: GPIO0 PIN03 (push-pull)
